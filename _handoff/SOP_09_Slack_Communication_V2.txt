
SOP 09
Slack Communication
How to talk to the team, the agents, and SmartSuite — without breaking the automation.

TL;DR — In 30 Seconds
Channel Map
RequityAI Slack has 4 types of channels. Each has one job. Post in the wrong place and your message gets lost — or worse, goes to the client.
Current Client Channels
When a new client is onboarded, both channels are created automatically. You'll be added to both.

Communication Rules
Respond to task notifications within 1 hour during working hours.
Use threads for replies. Never reply in the main channel body.
Use emoji reactions to acknowledge:
✅ = Done / Acknowledged
👀 = Seen, working on it
❓ = Need clarification
Do not DM Andrew unless it's urgent and private. Use the appropriate channel.
Do not use @channel or @here. Andrew only.
Keep messages short and actionable. State the issue, what you tried, what you need.
No personal conversations in work channels.
Escalation — If Something's Broken or Urgent
Post in #team-<client> (or #team-operations if cross-client) with the client name and issue.
No response within 30 minutes AND blocking a live campaign? DM Andrew directly.
System alert that affects a live campaign? DM Andrew immediately.
What NOT to Do
Don't create new channels without Andrew's approval.
Don't invite external people to any channel without Andrew's approval.
Don't discuss client information in #all-requityai.
Don't post free-form task updates — always use the structured format (Section 7).
Don't use Slack for file storage. All files go to Google Drive.
Don't ever post structured /update messages in #client-<client> channels.
Quick Reference Card

Structured Message Format — REQUIRED
The Three Agents
Three automation agents speak to you in Slack. Recognising their messages helps you know what action to take.
When to Use a Structured Message
Use a /update message any time something should be recorded in SmartSuite. That includes:
Completing a task
Flagging a task as blocked
Reporting a campaign build is ready for QA
Confirming an onboarding step is done
Flagging a client issue
Reporting video / creative status
Logging a conversation outcome
Responding to a Campaign Intelligence Agent directive
Acknowledging an Operations Agent reminder
If your message is a question or discussion, you do NOT need the structured format. Only use it when the result should update a SmartSuite record.

The Format
Every structured message starts with /update [APP] on the first line, then field: value pairs on each subsequent line.
Rules:
/update tag and app name MUST be on the first line.
Client name MUST match SmartSuite exactly. "Quick Home Buyers" — not "QHB" or "quick home".
Each field on its own line. Don't combine.
Status values MUST use exact SmartSuite dropdown labels (listed below).
Notes is optional but encouraged.
Don't add extra fields. Only use the ones listed for each app.

Agent-to-VA Message Format
When the agents post structured messages to you, they look like this:
Your action: Go to Ads Manager → Audiences → Create Custom Audience → Video → use the exact specs above. When done, post a /update Tasks message.
Your action: Read and acknowledge with 👀. If anything is yours, take action.
Common Mistakes — Don't Do This
Free-form: "Hey I finished the campaign for QHB, it's the probate one in Dallas, 3 ad sets" — won't parse, no record updated.
Abbreviated client name: "Client: QHB" — won't match SmartSuite. Use the exact full name.
Made-up status value: "Status: Finished" — must be an exact SmartSuite dropdown label.
Multiple updates in one message — post each as a separate /update.
Ignoring agent specs — if Campaign Intelligence says 25% / 50% with 30-day lookback, don't use 75% / 14-day.
Posting structured /update messages in #client-<client> — never. Those are client-facing.
What Happens After You Post
SmartSuite Sync Agent reads your message within 60 seconds.
It parses the fields, finds the matching record, updates it.
Bot reacts ✅ if processed successfully.
Bot reacts ⚠️ if it can't parse — check your format and repost.
If you see ⚠️, review your message against this SOP and post a corrected version.
