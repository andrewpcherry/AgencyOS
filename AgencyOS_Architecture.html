1. What AgencyOS Does

RequityAI runs Facebook ads for real estate investors (wholesalers) who buy distressed properties. The business model is the Algorithmic Targeting Content Flywheel: investors record talking-head videos addressing distressed seller situations (probate, foreclosure, code violations, inherited properties), and RequityAI runs Facebook ad campaigns using these videos with a compounding retargeting system. Revenue comes from setup fees ($1,000–$6,000) plus monthly retainers ($1,500–$3,500).

AgencyOS is the fulfillment automation system that removes the agency founder (Andrew) as the operational bottleneck. It connects sales (Close CRM), operations (SmartSuite), communication (Slack), automation (n8n), content (Google Drive), performance data (Windsor.ai), and AI decision-making (Claude) into a single cohesive system where a VA can execute the entire client lifecycle with minimal oversight.

SmartSuite Command Center

The operational source of truth. 8 apps track every entity from lead to payment. VAs work here daily. Every other system reads from or writes to SmartSuite.

Close CRM Sales

Andrew's sales tool. Tracks leads, calls, and deal stages. Two n8n workflows sync Close → SmartSuite every 12 hours. Close is write-only for Andrew; SmartSuite is the downstream consumer.

n8n Cloud Automation Engine

22 active workflows handle all inter-system data movement, alerts, and AI agent orchestration. Mix of scheduled (every 12h, 6h, daily) and event-driven (Slack messages).

Slack Communication

Two-way bridge between VAs and the system. VAs receive task notifications and send /update commands that write back to SmartSuite. Agents post briefings and alerts.

Google Drive Content Store

Each client gets a Drive folder with subfolders for Scripts, Raw Video, and Ad Creative. SmartSuite stores the folder URL; n8n creates folders automatically on client creation.

Windsor.ai Performance Data

Pulls Facebook Ads metrics (spend, CPL, thruplays, leads) every 12 hours via API. Data writes to SmartSuite Campaign records for reporting and AI analysis.

Three AI agents run inside n8n workflows, each calling the Anthropic API (Claude Haiku) for specific decision-making tasks.

Input: All live campaign data (spend, CPL, leads, thruplays, saves, comments, DMs) from SmartSuite

Output: Per-campaign decision written to Optimization records: Keep Running, Cut, Retarget Test, Lead Ad Candidate, or Swap Creative, with reasoning

Impact: Automates the most time-consuming analytical task — reviewing campaign performance and deciding what to do next

Ops Supervisor Agent Monitor

Schedule: 3x/day (8am, 2pm, 8pm ET, Mon-Fri)

Input: Aggregated system state across all SmartSuite apps — client statuses, task queues, onboarding progress, campaign health

Output: Narrative health report posted to Slack + DM to Andrew

Impact: Andrew gets system-wide situational awareness without checking any dashboards

SmartSuite Sync Agent Data Bridge

Trigger: Real-time (Slack event)

Input: VA /update messages in Slack

Output: SmartSuite record updates + ✅/⚠️ Slack reaction

Impact: VAs can update the database without leaving Slack — reduces context switching and friction

9. Pressure Test — Weaknesses & Recommendations

This section is the honest assessment. Not affirmation — critical analysis.

WEAKNESS 1: Polling Architecture — 12h Latency on Critical Paths

Problem: 16 of 22 workflows use scheduled polling (every 12 hours). When a VA marks a campaign as "QA Ready" in SmartSuite, it can take up to 12 hours for the QA checklist to appear in Slack. Same for task assignments, onboarding progression, and blocked task alerts. This creates a sluggish system where the VA is waiting for the machine to catch up.

Impact: High. A VA who finishes a campaign build at 9am won't see the QA notification until 9pm at worst. This breaks the promise of "real-time operations."

Fix: SmartSuite has webhook support (Zapier/Make triggers on record changes). Replace the 12h schedules with SmartSuite webhooks for the 6 most time-sensitive workflows: Task Assigned, Onboarding Progression, Prerequisites Met, Campaign QA Ready, Task Blocked, and 72hr Review Trigger. Keep 12h polling for data sync workflows (Close CRM, Windsor) where lag is acceptable.

Effort: Medium. Each workflow needs its trigger node swapped from Schedule to Webhook, and SmartSuite automations configured to fire on record change.

WEAKNESS 2: No Error Recovery or Retry Logic

Problem: Every workflow is fire-and-forget. If a SmartSuite API call fails (rate limit, timeout, transient error), the workflow errors silently and moves on. There's no retry, no dead-letter queue, no alert that data was lost. The only way to know something failed is to check n8n's execution logs manually.

Impact: High. A failed Pipeline Sync means Close CRM deals aren't reflected in SmartSuite. A failed Windsor pull means campaigns show stale metrics. A failed Intelligence Agent run means no optimization decisions for 12+ hours.

Fix: Add a global error handler workflow. n8n supports error workflows — when any workflow fails, it triggers a designated error handler that posts to a #system-errors Slack channel with the workflow name, error message, and timestamp. Add simple retry logic (n8n's built-in retry on failure) to the 5 most critical workflows.

Effort: Low. One error handler workflow + enable retry on 5 workflows.

WEAKNESS 3: Hardcoded API Keys in Code Nodes

Problem: The SmartSuite API token (Token 716c2356...), Close CRM API key, Windsor API key, and Anthropic API key are all hardcoded as string constants inside n8n Code nodes. If any key rotates, every workflow that uses it must be manually found and updated. We just experienced this with the Close CRM key — 2 workflows had to be patched.

Impact: Medium. Key rotation is infrequent but when it happens, it's a fire drill. Also a security concern — API keys are visible to anyone with n8n read access.

Fix: Move all API keys to n8n credentials or environment variables. Reference them via this.getCredentials() or $env.SMARTSUITE_TOKEN instead of hardcoding. This centralizes key management and supports rotation without code changes.

Effort: Medium. Requires touching every Code node in ~18 workflows, but it's a mechanical find-and-replace.

WEAKNESS 4: Single-Threaded Client Matching

Problem: The Sync Agent and several workflows identify clients by title string matching. If two clients have similar names (e.g., "Smith Properties" and "Smith Properties LLC"), the wrong record could be matched. We already hit this — the agent matched "Sunlit Properties" instead of "Ritsel Homes" before the exact-match fix.

Impact: Medium. The exact-match fix helps but creates a new problem: the VA must type the client name exactly as it appears in SmartSuite, including capitalization and spacing. Any typo → "Client not found."

Fix: Add a client alias system. When a Client record is created, generate a short code (e.g., "RSH" for Ritsel Homes). VAs can use either the full name or the code. The Sync Agent checks the code first (fast, unambiguous), then falls back to exact title match.

Effort: Low. Add a client_code field to Clients, populate on creation, update the Sync Agent's lookup logic.

WEAKNESS 5: No Onboarding SLA Enforcement

Problem: The 19-step onboarding checklist tracks progress but doesn't enforce timing. A client could sit at "Video Brief Sent" for 3 weeks with no automated follow-up. The Onboarding Health Monitor exists but is manual-trigger only — no one remembers to run it.

Impact: High. Onboarding delays directly impact time-to-revenue. A client who signed 3 weeks ago and still hasn't recorded videos is a churn risk.

Fix: Put the Onboarding Health Monitor on a daily schedule. Add SLA thresholds: if any step has been "In Progress" for 5+ days, auto-escalate to Andrew via Slack DM with the specific stuck step. Track step_started_date on each onboarding step to measure time-in-step.

Effort: Medium. Change trigger to daily, add date tracking fields, add SLA comparison logic.

WEAKNESS 6: Windsor.ai Campaign Name Matching is Fragile

Problem: The Windsor workflow matches Facebook campaign data to SmartSuite records by campaign name string. It uses a loose includes check. If the campaign naming convention isn't followed exactly, metrics land on the wrong record or get dropped entirely. There's no report of unmatched campaigns.

Impact: Medium. Silent data loss — if a campaign is misnamed, its metrics disappear into a void. Andrew sees $0 spend on a campaign that's actually running.

Fix: Add an "unmatched campaigns" report. After the Windsor pull, any campaign data that didn't match a SmartSuite record should be collected and reported in Slack. Also consider storing the Facebook Campaign ID on the SmartSuite record for deterministic matching instead of name-based fuzzy matching.

Effort: Low for the report; Medium for the ID-based matching.

WEAKNESS 7: Claude Intelligence Agent Has No Feedback Loop

Problem: The Campaign Intelligence Agent makes decisions (Keep Running, Cut, etc.) but never learns whether those decisions were correct. There's no mechanism to track whether a "Cut" decision was followed and what happened after. The AI can't improve its decision quality over time.

Impact: Low right now (decisions are reasonable), but limits long-term value. Andrew can't see the agent's hit rate.

Fix: Add a decision_outcome field to Optimization records (Correct / Overridden / Pending). When Andrew or the VA overrides a decision, log the override reason. Periodically include past decision outcomes in the Intelligence Agent's prompt so it calibrates to RequityAI's specific performance thresholds.

Effort: Low for the field; Medium for the feedback-in-prompt loop.

WEAKNESS 8: No Backup or Disaster Recovery

Problem: SmartSuite is the single source of truth with no backup. If data is accidentally deleted or corrupted, there's no recovery path. n8n workflows are cloud-hosted with no export backup. SOPs are in Google Docs (versioned, but only if someone remembers to check history).

Impact: Low probability, catastrophic impact. Losing the SmartSuite data means losing all client records, campaign history, and operational state.

Fix: Add a weekly n8n workflow that exports all SmartSuite records to JSON files in Google Drive. This gives a rolling 4-week backup with no manual effort. Also export n8n workflow definitions weekly via the API.

Effort: Low. One new workflow that iterates through 8 apps and saves JSON to Drive.
